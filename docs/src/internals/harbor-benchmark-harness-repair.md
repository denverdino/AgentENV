# Harbor benchmark 驱动修复方案

日期：2026-10-10。状态：用户已批准并确认执行；实现与两机无模型工程验收已完成。
本文描述设计与边界，实际覆盖与证据见 [集成记录](../../../HARBOR_INTEGRATION.md)。

## 目标与已授权范围

用户要求停止当前模型评测、修复测试方案，并在下一次 benchmark 前清理磁盘。
两台服务器是专用测试机，不长期保留过期测试过程数据。
评测用于观察 AgentENV + Dragonball 的稳定性、通用性及任务通过率；使用
Qwen，不增加 Docker 对照。已通过环境资格的 74 项为后续模型输入，12 项
未合格任务记录并跳过。修复验收不调用模型，不自动重新启动正式评测。

每台节点固定 64 CPU / 128 GiB，每个 guest 4 CPU / 8192 MiB；并发上限
8 个 sandbox。已有可复用的 OSS 模板、OCI 归档和 uv 下载绑定继续使用。
原任务、verifier、阶段超时、首次 guest 身份和初始工作区检查保持一致。
新候选、清理回执和新运行目录独立保存，不改写历史成绩或冻结候选。

## 已证实的问题

1. 外层控制器启动整批 Lab，等待最慢任务结束，再释放资源并开始下一批。
   Harbor 0.24.0 自身支持空位补充，但外层批次屏障使服务器长期低并发。
2. 磁盘预算按每任务运行盘 10 GiB、完整模板根盘 10 GiB、完整内存
   8 GiB 和镜像导入大小累计；复用现有模板仍走模板构建的预留路径。
3. storage_mb=10240 只进入预算和回执，未传为实际磁盘限制。
   现有模板继承 OCI 转换的 64 GiB 虚拟盘，guest 文件系统约 63 GiB。
   共享镜像层和按写入增长的 writable upper 不等于预分配 64 GiB。
4. 控制器 required_bytes 记录了下一个被拒绝批次的预算，而非已选批次。
5. 历史测试数据累计，B 可用空间约 67 GiB；清理不应等评测阻塞后才做。

## 选择的实现边界

使用一个持久 Lab 和 AgentENV 服务，每机至多 8 个 worker。每个 worker
执行原生 Harbor 单 trial Job，完成、确认 sandbox 删除和资源收尾后立即
补位。复用现有 CLI、输入校验、模板准备、资源清理及宿主租约，不并行启动
多个独占 Lab，不修改 Harbor 上游或依赖其私有调度属性。

节点服务、代理和 registry 全程只创建一份。镜像和模板按即将执行的任务
增量准备；同一不可变输入只准备一次，每个 Job 获得自己的不可变清单。
只绑定当前任务需要的 uv 缓存。模板 reuse 缺失则明确失败，不悄悄冷启动。
probe、builder 与模型 trial 共用 sandbox 槽位，不额外启动第九个 VM。

磁盘容量采用现有模板的真实容量，明确记录虚拟盘、guest 文件系统、任务
声明和实际宿主占用。当前模板没有安全缩容能力；本轮不将 64 GiB 模板
强行缩为 10 GiB，也不把任务声明写成已实施硬限额。若需要 10 GiB 硬限额，
另做镜像转换／模板重建或配额实现，不混入此次驱动修复。

## 磁盘准入与运行保护

建立显式阶段预算：缓存命中的数据已经占用宿主空间，体现在 free bytes
中；只为尚未兑现的导入、模板下载／物化和 trial 写入增量保留空间。
共享输入按内容身份计一次，私有可写数据按活跃 trial 分别计。
模板准备和模板 reuse 使用不同预算，不再无条件重复预留完整模板。
内存快照虽来自 OSS，可能形成本地数据，因此按已下载／未物化空间和
原生缓存行为核对预算，不能将其增量一律记为零。

任务声明的 10 GiB 可作为预期写入量，不能作为最坏峰值保证。
保留至少 20 GiB 宿主安全余量。准备前、启动前重新检查实际 free bytes
和活跃未兑现预留；持续采集磁盘水位和实际占用。低水位停止新准入，必要时
有界终止当前 trial，归为环境容量中断，不能计为模型解题失败。
释放槽位不代表磁盘已回收：已经形成的缓存／失败数据仍由 free bytes
反映。没有在途工作且无法准入时记录 blocked_disk 及待办，结束队列。

每次保存实际获准 trial 的预算和阶段明细，修复 rejected proposal 误记。
原始输入、准入决策、并发事件和空间变化可追溯；最大并发是 8，不能在
没有足够空间时绕过准入来凑满。

## 启动前清理

所有 benchmark 入口先取得宿主独占租约、确认旧评测已停止，再做清理与
预检。历史专用测试目录先生成精确清单，核对所有者／目录身份、时间、pin、
进程、设备、挂载及输入引用，再删除获准的过期过程数据。
避免 Docker 全局 prune 或不受限 glob 删除。

保留本轮结果、token、轨迹、错误和清理回执；持久 OCI 归档、依赖缓存、
运行二进制／guest 资产及 OSS 仓库不能因位于历史目录就被删除。
目前 inputs.json 仍引用 /var/tmp/adr1005/deps 和 full-fixtures；清理必须
保留这两个依赖树，或先完成摘要核验的迁移并更新所有引用。
过期过程数据不长期保留，失败现场只保留当前诊断所需代表；清理记录实际
回收空间。准备、准入不足时在模型调用前失败。

## 结果与终止

保留每个原生 Harbor Job 的 config、lock、result、token、耗时、轨迹、
verifier 和错误日志。模型失败、环境异常、用户取消与待办分别统计。
结束事件／CLI exit 0 不代替 sandbox 删除确认。清理失败停止补位，保留
原始错误与 cleanup 错误。受控终止只执行一次整 Lab 清理和宿主恢复。
当前中断试验不生成伪造评分，不改写旧 agentenv.json 为自然完成。

## 验收

1. 先补失败测试：快任务完成后，第九项在慢任务结束前启动；清理未完成
   不补位，所有准备／probe／trial 合计不超过 8。
2. 磁盘夹具覆盖：缓存命中不重复预算、reuse 不预算 builder、私有增量
   独立预留、实际选中预算正确、低水位停止准入、取消释放预留且不伪造回收。
3. 清理夹具覆盖：活动、被引用、pin、目录身份变化和未知路径拒绝删除；
   明确过期自有数据可清理；二进制、依赖和共享模板保留。
4. 两机同一冻结候选、非 root 全套 Harbor 驱动检查及摘要前后校验。
5. 不调用模型的真实 VM 长短任务验证持续补位、8 个槽位、4c8g、64c128g、
   guest 容量回执、磁盘水位以及中断后无进程／设备／cgroup 残留。
6. 新 benchmark 启动前有清理和容量回执；正式模型评测需后续明确启动。


实现保守边界：活跃私有分配尚无逐 sandbox 可核验归属，不以宿主全局 free
变化抵扣其预留；先保留典型写入＋恢复预算，删除确认后释放。共享源层按
committed catalog 的真实大小计算，自有缓存物理块可抵扣。实际低水位阻止
启动；负 headroom 只影响新准入，不据此取消已准入且实际水位仍安全的 trial。
自动历史清理只支持超过 24 小时、有资源记录及同 boot M4 clean 审计的 Lab，
其他历史目录继续需要精确人工清单，不能将此入口宣称为任意历史数据 GC。
