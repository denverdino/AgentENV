## 隔离与生命周期

测试控制器为 root，仅负责 namespace/cgroup/设备准备；server、runner 和测试
工作负载使用 `aenv`，只保留现有 capability runner 的权限。每次运行建立短路径
`/var/tmp/db-m4.*`，节点 A/B 各自拥有 net/mount/PID namespace、home/run/deps、
cache 和 cgroup v2。节点看不到另一节点的可写目录；各自挂载 proc/sysfs，
避免读取宿主机 PID 或网络接口。共用只读二进制与 guest assets。

外层测试 net namespace 内建立桥接网络，连接 A、B 和测试仓库端点；不修改
宿主机路由、防火墙或全局网络命名空间。初始每节点 memory.max=12 GiB、
cpu.max=400000/100000、pids.max=2048，禁止 swap。这些是演练容量上限，
不是性能 SLO。先验证同端口并存、跨节点 HTTP、断网恢复、peer state 不可读，
再启动 VM。失败和超时必须回收该次运行的 cgroup 全部进程；日志保留，
测试状态不自动递归删除。

## 功能场景

通过真实 HTTP server API 执行冷启动、guest RAM/盘标记写入、卷挂载、capture
发布到独立 S3 测试仓库。源进程退出后，B 从空快照缓存恢复，验证 RAM/盘/卷
内容及新的 sandbox ID。相同 ABI 可以恢复，异类 backend/ABI 应在资源分配前拒绝。
断开 B 网络使恢复失败，恢复网络后重试成功，仓库记录不丢失；源节点进程故障
不影响已经提交的快照。

分别保留 DB、FC 入口与模板名字。回滚演练只把新建请求送往 FC；DB paused
仍在 DB 入口 same-ID resume，FC paused 仍在 FC 入口恢复。测试驱动直接选择
入口，不把这个测试选择器包装成生产 gateway 的能力。
